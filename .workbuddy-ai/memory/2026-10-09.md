## Langkah 3: Decap CMS Admin Panel

**Task:** Add Decap CMS (formerly Netlify CMS) to provide a visual admin panel for content management without coding.

**What was done:**
- Split `data.json` into 5 separate content files in `content/` directory:
  - `content/settings.json` (site, navigation, hero, footer)
  - `content/about.json` (bio, stats, specializations)
  - `content/portfolio.json` (filters + photo items)
  - `content/services.json` (service offerings)
  - `content/contact.json` (contact cards, info boxes, CTA)
- Updated `script.js` `loadData()` to use `Promise.all` fetching all 5 content files and merging into `siteData`
- Created `admin/index.html` — Decap CMS entry point (loads CMS from unpkg CDN v3.6.0)
- Created `admin/config.yml` — comprehensive CMS configuration with 5 collections:
  - Each content file mapped to a file collection with `format: json`
  - All fields defined as CMS widgets (string, text, number, image, select, list, object)
  - Portfolio category uses `select` widget to prevent typos
  - Contact card type uses `select` widget
  - Image fields use `image` widget (supports both upload and external URLs)
  - Backend: GitHub with PKCE auth (no proxy needed, just needs OAuth App client ID)
- Created `images/` directory for CMS media uploads

**Architecture:**
```
├── index.html          # Frontend skeleton
├── styles.css          # All styling
├── script.js           # Fetches content/*.json, renders everything
├── content/            # Data layer (edit via CMS or directly)
│   ├── settings.json
│   ├── about.json
│   ├── portfolio.json
│   ├── services.json
│   └── contact.json
├── admin/              # CMS admin panel
│   ├── index.html      # Decap CMS entry
│   └── config.yml      # CMS field configuration
├── images/             # CMS media uploads
└── data.json           # Old backup (no longer used)
```

**User setup required:**
1. Create GitHub OAuth App (settings/developers)
2. Set callback URL to `.../admin/`
3. Copy Client ID to `admin/config.yml` → `app_id`
4. Push to GitHub → access `/admin/` to manage content

## Langkah 4: Image Upload & Optimization System

**Task:** Add automatic image optimization so photos uploaded via CMS are automatically compressed and resized, plus add frontend lazy loading for performance.

**What was done:**
- Created `.github/workflows/optimize-images.yml` — GitHub Action that triggers on push when `images/**` changes
  - Skips bot commits (`[skip ci]`)
  - Sets up Node.js 20, installs sharp, runs optimize-images.js
  - Auto-commits optimized images back to repo
  - `permissions: contents: write` for push access
- Created `scripts/optimize-images.js` — sharp-based image processor
  - Reads all images from `images/` directory
  - Resizes to max 1920px width (maintains aspect ratio, `withoutEnlargement: true`)
  - Compresses: JPEG (mozjpeg q80), PNG (q80, compressionLevel 9), WebP (q80), AVIF (q80)
  - Only replaces original if optimized version is smaller (prevents re-optimization degradation)
  - Uses temp `.tmp` file then rename pattern
- Created `scripts/package.json` — `sharp: "^0.33.0"` dependency
- Created `.gitattributes` — `* text=auto eol=lf` + binary markers for image types
- Updated `script.js`:
  - `renderAbout()`: Added `loading="lazy" decoding="async" onerror="this.classList.add('img-broken')"` to `<img>` tag
  - `renderPortfolio()`: Same lazy loading + onerror attributes added to all portfolio images
- Updated `styles.css`:
  - Added `.img-broken` fallback styling (gradient background + Font Awesome image icon centered)

**Final architecture:**
```
├── index.html

├── script.js
├── content/            (5 JSON data files, editable via CMS)

├── scripts/            (Image optimization tooling)
│   ├── optimize-images.js
│   └── package.json
├── .github/workflows/  (GitHub Action for auto image optimization)
│   └── optimize-images.yml
├── .gitattributes

```
